Safe evidence publishing

Portal security and log hygiene

Validation evidence is useful only when it can be published without exposing credentials or customer data.

  • Use synthetic or masked test data.
  • Never write access tokens, passwords, API keys, customer payloads, or private certificates to logs.
  • The portal sanitizes common credential patterns before publication, but source pipelines remain responsible for safe logging.
  • Keep private-repository portals private through GitHub Enterprise Pages, an internal static host, or authenticated object storage.
  • Set retention based on audit and regulatory requirements.
  • Do not publish raw production traces unless reviewed and de-identified.

Published artifacts

The portal publishes sanitized copies of text-based logs and reports. Binary artifacts are copied as supplied; teams should avoid uploading secrets or production data in binary attachments.
